# 第一批無損處理優化：v0.3.13

日期：2026-10-17。基準版本 `6dbcc3093caafbbd85b4549c659fe362080b22fb`（v0.3.12）。完整樣本與參數見 [原始結果 JSON](performance-2026-10-17.json)。

## 已完成

- 單目標分割仍自動產生 7 個相同名稱、格式與內容的 PNG。合併與實例結果相同時，以獨立檔案複製取代 3 次重複 PNG 編碼，不使用硬連結。多目標仍保存所有實例。
- 遮罩合併去掉多餘 bool 複製；alpha 只產生一次；RGBA 暫存儘早釋放。預覽疊色以 128 行分塊處理，保留原本 float64 運算及截斷規則，沒有以精度換記憶體。
- SAM3 結果轉換重用 Ultralytics 已解碼圖片／尺寸；常駐工作程序不再要求未使用的 RGB 副本。同尺寸遮罩略過無效果的 resize。舊呼叫端預設仍收到 RGB。
- 縮圖、預覽與全圖共用 **48 MiB / 160 項**有界編碼快取，超大項目不保存；同一個可快取項目的並發請求共用編碼，檔案路徑／mtime／大小／顯示尺寸決定快取鍵。原始下載不經快取或 JPEG 轉碼。這是壓縮後 bytes 預算，不是整個程式 RAM 上限。
- 任務輪詢存在請求時略過新輪詢，明確操作仍可要求刷新；較舊回應不能覆蓋已套用的新回應。
- 日誌新增 SAM3 呼叫、遮罩轉換、NPZ 保存、應用匯出與整體操作耗時；YOLO / SAM3 增加 PyTorch allocated、reserved 與工作程序生命期峰值。這些不包含其他程序或 ORT，不能與整卡進度條混用。CUDA 呼叫非同步，分段 CPU wall time 不等同純 GPU kernel 時間。

## 本機結果

Python 3.12.14，合成 RGB 圖片，固定單目標模型替身。先準備執行一次，前後交替測量，各 5 次；端到端包含分割輸出操作，但 **不包含真實模型推理**。PNG 使用相同預設壓縮參數。

| 範圍 | 修改前 | 修改後 | 結果 |
| --- | --- | --- | --- |
| 1600×1000 單目標處理，中位數 | 1026.45 ms | 651.64 ms | 約減少 36.5%；7 個 PNG 逐檔 SHA256 相同 |
| 同圖 JPEG 編碼／快取查找，中位數 | 35.4158 ms | 0.0008 ms | 命中快取的純函式時間；不含 HTTP、瀏覽器解碼及繪製 |
| 6000×4000 全圖疊色，跟蹤分配峰值 | 1167.36 MiB | 103.89 MiB | tracemalloc 記錄的 Python/NumPy 分配，非程序 RSS、非顯存；輸出像素相同 |
| 同次 24MP 疊色耗時 | 1802.93 ms | 1616.34 ms | 單次參考，不能當作穩定加速比例 |

小樣本、固定遮罩與合成照片只驗證這些處理開銷，不代表真實相片、整體工作負載或 RTX 5070 Ti 的加速比例。快取首次未命中仍需完整編碼。

## 驗證與重現

新增回歸覆蓋：所有通道值的疊色一致性、單／多目標每個匯出檔像素、獨立副本、快取 byte 預算與 LRU、並發去重、錯誤恢復、EXIF、檔案變更失效、原檔下載，以及工作程序遮罩協定。既有取消、模型切換、匯出與持久化測試保留。

另在實際 Ultralytics + Torch CPU + OpenCV 環境，用真實 `Results` 容器檢查同尺寸／需縮放遮罩及舊 RGB 回傳，像素與原流程一致；未使用完整 SAM3 權重或驗證 5070 Ti GPU 推理。

在有 Git 歷史的原始碼倉庫執行（基準程式從指定的受信任本機 Git 版本載入）：

